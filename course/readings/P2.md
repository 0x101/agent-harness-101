## In one paragraph

The paper argues that an agent should act by writing Python code that an interpreter runs, not by filling in JSON or a fixed text format. The set of moves open to the model, its **action space**, then covers whatever a program can do: combine tools in one step, loop, keep variables, use libraries and read error messages. The authors call this **CodeAct**. Testing 17 models, they report that code actions match or beat JSON and text, with the largest gains on tasks that need many tools.

## How to read it for this course

About 20 minutes.

- **Read closely:** the [abstract](https://arxiv.org/html/2402.01030) and [1 Introduction](https://arxiv.org/html/2402.01030#S1), with its four numbered advantages.
- **Skim:** [2.3](https://arxiv.org/html/2402.01030#S2.SS3), where the headline numbers come from, and [Appendix F](https://arxiv.org/html/2402.01030#A6), the prompt each format was given.
- **Skip:** [3](https://arxiv.org/html/2402.01030#S3), which fine-tunes open models.
- **S06, Designing tools.** Read it after A2, which argues for purpose-built tools. For each of the four advantages, ask whether your `bash` tool gives it and whether `view_file` or `edit` would take it away. The session's log asks where the two disagree.

## What it shows

- **Code is at least as good for single calls.** On API-Bank, one tool call per action, CodeAct was comparable or better for most models. Closed-source models did well with JSON, which the authors suspect comes from targeted fine-tuning ([2.2](https://arxiv.org/html/2402.01030#S2.SS2)). A measurement.
- **Code helps most when tools must be combined.** On M3ToolEval, 82 tasks the authors wrote, CodeAct had the higher success rate for 12 of 17 models and needed fewer turns for 12 of 17 ([2.3](https://arxiv.org/html/2402.01030#S2.SS3)). The best case is up to 20% absolute improvement with up to 30% fewer actions ([1](https://arxiv.org/html/2402.01030#S1)). A measurement.
- **Error messages are free feedback.** An agent working in Python reads the interpreter's errors and fixes its own code ([2.4](https://arxiv.org/html/2402.01030#S2.SS4)). An example, not a measurement.

## Where it is weak

- No task in the comparison involves a repository. M3ToolEval answers are checked by exact match, in domains such as web browsing and travel planning.
- The authors wrote the benchmark with the biggest gap, and there the JSON and text prompts allow one tool per action while the code prompt allows loops ([Appendix F](https://arxiv.org/html/2402.01030#A6)). Part of the gap is built into the setup.
- On M3ToolEval, the JSON baseline is JSON written inside the reply after `Action:`. The paper never tests an API's own tool calling, which `agent.py` uses.
- The paper (version 4, June 2024) tests models such as claude-2 and gpt-4-1106-preview.
- A2 and P1 take the other side: a narrower, purpose-built interface prevents mistakes.

## What it means for your harness

Your starter already makes code actions. Its one tool, `bash`, takes a program, and `run_bash` returns stdout and stderr, so error messages reach the model. P2 is the case for leaving it that way.

One difference matters. CodeAct sends actions to an interactive Python (Jupyter Notebook) environment ([Appendix E](https://arxiv.org/html/2402.01030#A5)). `run_bash` starts a fresh shell per command, so a shell variable or a `cd` is gone by the next step.

The tools you add in S07 and S08 each do one thing, and give up some of what P2 values: composing steps, and the program's own error messages. S09 measures whether the trade paid.

## In their words

> "LLM agents are typically prompted to produce actions by generating JSON or text in a pre-defined format, which is usually limited by constrained action space (e.g., the scope of pre-defined tools) and restricted flexibility (e.g., inability to compose multiple tools). This work proposes to use executable Python code to consolidate LLM agents' actions into a unified action space (CodeAct)."
>
> Source: [Abstract](https://arxiv.org/html/2402.01030). Wang et al. 2024, CC BY 4.0.

> "Furthermore, using the interactive Python interpreter for code execution allows automated error messages that help the LLM agent 'self-debug' their actions in a multi-turn interaction and eventually complete the human user's request correctly."
>
> Source: [2.4 CodeAct Benefits from Multi-turn Interactions and Existing Software Packages](https://arxiv.org/html/2402.01030#S2.SS4). Wang et al. 2024, CC BY 4.0.
