## In one paragraph

Mitchell Hashimoto describes, in six steps, how he went from AI skeptic to trying to keep an agent running all the time. Step 5, the part this course assigns, names a habit he calls **harness engineering**: each time an agent makes a mistake, you build something so that it never makes that mistake again. The fix is either a line in the agent's instruction file or a real tool, such as a script that runs a filtered set of tests.

## How to read it for this course

Step 5 takes about five minutes, the whole post about fifteen.

- **Read closely:** [Step 5: Engineer the Harness](https://mitchellh.com/writing/my-ai-adoption-journey#step-5-engineer-the-harness).

## What it shows

This is one developer's experience, with no measurements of how well agents did.

- **Fast feedback is the lever.** Agents are most efficient when they get it right first time, and the surest route is fast, high-quality tools that tell the agent when it is wrong ([Step 5](https://mitchellh.com/writing/my-ai-adoption-journey#step-5-engineer-the-harness)).
- **Each mistake becomes a line.** For simple faults, such as running the wrong commands, he adds a line to AGENTS.md. In Ghostty's file each line comes from a bad behaviour, and he reports the lines almost completely stopped those behaviours ([Step 5](https://mitchellh.com/writing/my-ai-adoption-journey#step-5-engineer-the-harness)).
- **Or a real tool.** Scripts to take screenshots or run filtered tests, usually with a line in AGENTS.md so the agent knows they exist ([Step 5](https://mitchellh.com/writing/my-ai-adoption-journey#step-5-engineer-the-harness)).
- **Verification pays.** Given a way to verify its work, an agent more often than not fixes its own mistakes ([Step 2](https://mitchellh.com/writing/my-ai-adoption-journey#step-2-reproduce-your-own-work)).

## Where it is weak

- No counts. No fix has a before and after, so "almost completely resolved" is his impression.
- One person, whose only named project is Ghostty, in February 2026. He expects the post to date quickly.
- His harness wraps an agent someone else built. The post does not touch the loop, the tool interface or the context, which is most of what this course changes.
- A line per mistake makes the instruction file grow, and the post does not weigh that cost. B3, read in the same session, treats context as scarce.
- In its favour: he states he does not work for, invest in or advise any AI company.

## What it means for your harness

You own the whole harness, so both forms are open to you. A line of instruction is `SYSTEM` in `agent.py` now, and repo-local instruction files in S29. A programmed tool is what you build in S05 to S08, and the verification gate in S27.

Read the starter's `SYSTEM` with Step 5 in mind. It says to use the bash tool and to reply with a summary when done. It says nothing about running tests or checking the work.

The real difference is measurement. Hashimoto reports none for his fixes. You run the 12 tasks after each change, against the S02 baseline, and a fix that does not move the numbers comes out.
